# Auto Endcard Tool

Auto Endcard Tool 是一个 Windows 批量视频片尾拼接工具。v5.0 使用 NEUI 重构图形界面，并延续单比例、纯视频片尾处理：每次先选择 16:9、1:1 或 9:16，再扫描原视频目录，只为画面比例与所选视频片尾一致的文件生成结果。

## v5.0 NEUI 界面

- 使用 NEUI、Skia 和 GLFW 构建 GPU 加速界面。
- 统一为现代深色视觉，按“本次任务、路径设置、导出设置、进度、日志”分区。
- 中文字体统一使用 Microsoft YaHei UI，避免 Skia 默认字体缺少中文字形。
- 使用 Windows 原生文件与文件夹选择窗口，不再依赖 Tkinter/Tcl/Tk。
- 处理线程通过界面事件队列更新进度和日志，避免后台任务直接改写控件。
- 窗口关闭时仍会保存配置；处理过程中退出会先提示确认。

NEUI 当前仅支持 Windows，运行机器需要具备 OpenGL 兼容显卡。界面使用 GPU 渲染不代表视频使用 GPU 编码；视频编码仍为 libx264。

## 单比例处理方式

- 界面顶部选择本次生成比例。
- 每次任务只使用所选比例对应的一个视频片尾文件。
- 编码开始前，先探测片尾和全部原视频的画面比例。
- 片尾比例与所选比例不一致时，整个任务不会开始编码。
- 原视频比例不一致时跳过该文件，并在日志中记录。
- 原视频与片尾的分辨率可以不同，编码时统一拉伸到目标尺寸。
- 不再支持图片片尾，也没有图片片尾时长设置。

因此，同一个混合比例目录可以分别执行三次任务；每次只会输出一种比例。

## v4.0 精简内容

以下功能已经移除：

- “常规模式 / 包边模式”选择。
- 1:1、9:16 包边背景设置。
- 视频框位置、尺寸和比例锁定编辑器。
- 包边首帧预览。
- 包边模板保存与读取。
- `process_mode`、`preview_source`、`box_*`、`layouts` 等运行配置。

程序现在只有一条清晰的处理链路：选择比例 → 校验片尾 → 扫描原视频 → 筛选同画幅视频 → 裁剪并拉伸 → 编码输出。

旧版 `auto_endcard_config.json` 仍可读取；程序只提取当前有效设置，下次保存时会自动删除已经废弃的包边字段。

## 功能

- 递归扫描输入文件夹，并保留相对目录结构输出。
- 根据画面尺寸和旋转元数据识别 16:9、1:1、9:16。
- 顶部下拉框选择本次任务的唯一输出比例。
- 分别记忆三种比例最近使用的片尾路径，界面只显示当前选择的片尾。
- 编码前完成整个输入目录的比例扫描，保证不会混合输出。
- 支持裁剪原视频开头和结尾。
- 支持设置 FPS、CRF、编码速度和文件名后缀。
- 输出存在时可选择覆盖或跳过。
- 原视频或片尾没有音轨时自动补充静音轨道。
- 提供处理进度、实时日志、安全停止和打开输出文件夹功能。
- 自动保存本地配置。

## 目标规格

| 选择比例 | 输出尺寸 | 本次处理范围 |
| --- | ---: | --- |
| 16:9 | 1920 × 1080 | 仅 16:9 原视频和片尾 |
| 1:1 | 1080 × 1080 | 仅 1:1 原视频和片尾 |
| 9:16 | 1080 × 1920 | 仅 9:16 原视频和片尾 |

原视频和片尾都会直接拉伸到所选目标尺寸，不要求分辨率相同。无法在容差范围内匹配所选比例的视频会被跳过，并在日志中记录检测尺寸。

## 支持格式

原视频：

`.mp4`、`.mov`、`.m4v`、`.mkv`、`.avi`、`.webm`

视频片尾：

`.mp4`、`.mov`、`.m4v`、`.mkv`、`.avi`、`.webm`

## 快速使用

1. 在界面顶部选择本次生成比例。
2. 选择该比例的视频片尾文件。
3. 选择原视频文件夹和输出文件夹。
4. 按需要调整裁剪和编码参数。
5. 点击“开始批量处理”。程序完成全目录扫描后才会开始编码。

“停止”不会终止正在编码的 FFmpeg 进程；当前文件完成后，程序停止后续任务。

## 导出设置

| 设置 | 可选值或含义 | 默认值 |
| --- | --- | ---: |
| 裁剪开头/秒 | 从原视频开头移除的时长 | `0.0` |
| 裁剪结尾/秒 | 从原视频结尾移除的时长 | `0.0` |
| FPS | `24`、`25`、`30`、`60` | `30` |
| CRF 画质 | `16`、`18`、`20`、`22`、`24`，越小画质越高 | `18` |
| 编码速度 | `fast`、`medium`、`slow` | `medium` |
| 文件名后缀 | 添加到原文件名后 | `_endcard` |
| 覆盖同名输出 | 关闭时跳过已经存在的输出 | 开启 |

如果裁剪后剩余时长不超过约 `0.05` 秒，该视频会被跳过。

## 输出规则

输出格式固定为 MP4，并保留输入目录的相对结构：

```text
输入：input/level-01/demo.mov
输出：output/level-01/demo_endcard.mp4
```

编码参数：

- 视频：H.264 / `libx264`、`yuv420p`。
- 音频：AAC 192 kbps、48 kHz、双声道。
- MP4 启用 `faststart`。

输出文件夹可以位于输入文件夹内部，扫描时会自动排除该目录；但输入和输出不能设置为同一个文件夹。

## 运行源码

运行环境：Python 3.10 或更高版本、Windows 10/11 和 OpenGL 兼容显卡。界面依赖 NEUI，视频处理依赖外部 FFmpeg。

先安装运行依赖：

    python -m pip install -r requirements.txt

```powershell
python .\auto_endcard_tool.pyw
```

项目会依次查找：

1. `<程序目录>/tools/ffmpeg.exe` 和 `ffprobe.exe`。
2. 系统 `PATH` 中的 FFmpeg 和 FFprobe。

`tools/` 包含本地大文件，因此整个目录已被 Git 忽略。克隆项目后需要自行创建该目录并放入二进制文件，或配置系统 `PATH`。

## 测试

```powershell
python -m unittest discover -s tests -v
```

测试覆盖配置迁移、比例识别、全量预扫描、片尾比例拒绝、单比例筛选、拉伸滤镜、输出目录排除和输出路径生成。

## 构建 Windows 发布包

安装开发依赖：

```powershell
python -m pip install -r requirements-dev.txt
```

执行构建：

```powershell
.\build.ps1
```

构建结果位于 `dist/AutoEndcardTool/`。如果本地 `tools/` 存在，构建脚本会把 FFmpeg 和 FFprobe 复制到发布目录；使用 `-SkipTools` 可跳过复制。

## 源码结构

```text
AutoEndcardTool/
├─ auto_endcard_tool.pyw       # GUI 入口
├─ auto_endcard/
│  ├─ neui_ui.py               # NEUI 界面与线程事件调度
│  ├─ ui.py                    # 旧导入路径的兼容层
│  ├─ processor.py             # 批处理编排和文件扫描
│  ├─ media.py                 # FFprobe 探测与 FFmpeg 合成
│  ├─ config.py                # 配置读写
│  ├─ models.py                # 配置和任务数据模型
│  ├─ constants.py             # 格式、规格和导出选项
│  └─ paths.py                 # 程序目录与二进制查找
├─ tests/                      # 标准库 unittest 测试
├─ AutoEndcardTool.spec        # PyInstaller 构建配置
├─ build.ps1                   # Windows 构建脚本
├─ requirements.txt            # NEUI 运行依赖
└─ requirements-dev.txt        # 构建依赖
```

界面层不直接拼装 FFmpeg 命令；媒体处理、批处理、配置和路径查找均可独立测试或替换。

## 本地配置

程序在可执行文件旁保存 `auto_endcard_config.json`，该文件可能包含本地或网络绝对路径，因此已被 Git 忽略。

当前配置字段：

```text
input_dir, output_dir
target_aspect
outro_16x9, outro_1x1, outro_9x16
cut_head_seconds, cut_tail_seconds
fps, crf, preset, overwrite, suffix
```

## 注意事项

- 原视频与视频片尾必须属于同一目标比例，但分辨率可以不同；编码时会拉伸到目标尺寸。
- 图片文件不能作为片尾输入。
- 输入目录可以混有多种比例，程序只处理本次下拉框选中的比例。
- 同一目录下同名但扩展名不同的输入文件会生成相同的输出文件名。
- 当前版本使用软件编码 `libx264`，没有 GPU 编码选项。
- 根目录的本地配置、`tools/`、`build/` 和 `dist/` 均不会提交到 Git。
